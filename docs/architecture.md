# Architecture and trust boundaries

## The dispute being resolved

An analyst may present a national labor-force unemployment series as a claim about every adult, or reuse approval after changing a descriptive question into a causal one. DatasetCovenant makes the requested use, exact source version, bounded review result and counterpart acknowledgement separately attributable and immutable.

## Lifecycle

1. A researcher creates an owner-scoped ID, nominates a different analyst, commits six intended-use fields and exact SHA-256 hashes of two official response bodies. Optional parent ID and parent intent digest bind a revision lineage.
2. Only that analyst may capture sources. The contract fetches fixed official HTTPS endpoints, checks exact response hashes, checks WDI source/indicator/country/year identity, enforces a complete page and preserves raw bodies. `strict_eq` compares the captured output between validators.
3. The analyst requests assessment. Each validator independently assesses population, measurement and exclusions from the same frozen evidence. It must agree with the leader's three status values, then separately substantively audit the leader's original-source citations. Explanatory prose is leader-authored and not compared verbatim. Citations are line coordinates; stored quotes are copied deterministically from frozen source, not generated by the model.
4. Geography is matched deterministically against USA. Period is supported only when every requested year exists with non-null value; zero is present, not missing. Missing years are UNKNOWN because this extract does not prove that no wider source exists. Contradicted dimension dominates UNKNOWN, which dominates SUPPORTED. A causal-effect intended use is always at most UNKNOWN; metadata does not supply a causal design.
5. Only the researcher can acknowledge, and must provide the exact assessment digest. Receipt binds researcher, analyst, intent, source, assessment and unchanged verdict. There is no override or editing method.
6. Changed assumptions create a new covenant with parent commitment. The old record remains intact and its acknowledgement is not inherited. The old assessment digest cannot acknowledge the new revision.

## Narrow adapter

The API endpoints are fixed: SL.UEM.TOTL.ZS, WDI source2, USA,2020–2023. No arbitrary remote URL is fetched. Three narrative fields are 10–500 characters; period is bounded to21 years; responses to30KB. These bounds define the actual application scope. Country output is never generalized from USA to global/state analysis. Metadata is not expanded into sampling information absent from the record.

The normalized evidence has11 lines: profile, indicator ID/name/definition, organization, collection, country, interval, non-null/null year lists, explicit scope warning. The final warning is application-authored, not empirical evidence. Definite semantic judgments need substantive official lines3–5, supplemented by appropriate source context.

## UI and receipt handling

The browser provides recorded and live modes; the same real contract method names are called by browser and CLI. EIP-6963 chooses MetaMask rather than whichever extension last overwrote `window.ethereum`. Chain61999 is required. Writes show signing, pending consensus, execution success and errors separately. The complete intended call is saved locally before signing or broadcast. The returned hash is then saved before polling. An unknown broadcast result retains the intent and blocks another write; the user can supply an existing transaction hash without resending. Recovery compares receipt hash, actor, contract, complete ABI calldata and full-validator mode against the saved intent, then verifies contract state. A known hash cannot be replaced. Explicit wallet rejection can clear an unsigned intent; uncertain network failures cannot. ACCEPTED lifecycle alone is insufficient: explicit majority agreement, successful VM return and `leader_only:false` are required. Unknown or timed-out network results are not silently retried as new writes.

The harness journals the intended call before sending and records its hash before polling. A broadcast with uncertain outcome requires explicit hash recovery, never automatic duplicate submission. Each scenario uses a new owner-scoped immutable ID. A failed contract assessment is preserved rather than relabeled successful.

## Limits

- Model agreement does not establish objective correctness. Ambiguous metadata may produce disagreement or UNKNOWN.
- Hash pinning rejects source drift; it does not establish that the external source can never be wrong.
- Source country/date availability is not data accuracy, sampling representativeness or causality.
- Different addresses do not prove independent people. Demo accounts are all controlled by this project.
- Testnet results and recorded snapshots are evidence of those executions only; no reward, acceptance or commercial endorsement is implied.
